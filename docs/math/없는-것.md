# 이 저장소에 **없는** 것 — 축 2

> [[ws/cobot2/math/coordinate-transform|축 1]]은 "내 코드에 있는 수학"이다. 이 문서는 그 반대다.
>
> **왜 없는 것의 목록을 문서로 만드나:**

> 2. NotebookLM에 이 파일을 소스로 넣으면 질문의 조준이 정확해진다 —
>    "내가 모르는 것"이 명시돼 있으면 AI가 코드에서 없는 답을 지어내지 않는다.
>
> **이 목록이 줄어드는 게 진도다.**

## 공통 구조 — 내 코드는 "API 호출까지"다

네 코드가 이론과 끊기는 지점은 전부 같은 모양이다: **내가 호출은 하는데 안을 모르는 함수.**

```python
target_pos = list(td_coord[:3]) + robot_posx[3:]   # robot_control.py:141
movel(target_pos, vel=VELOCITY, acc=ACC)           # robot_control.py:151
```

이 두 줄이 축 1과 축 2의 **국경선**이다.
왼쪽(`td_coord`를 만드는 것)까지가 내가 한 일이고, `movel` 안쪽은 두산 컨트롤러가 한다.

**이게 나쁜 게 아니다.** 산업용 로봇을 쓰는 대부분의 엔지니어가 여기까지 한다.
중요한 건 **국경선이 어디인지 정확히 아는 것**이다.

---

## 1. 역기구학 (Inverse Kinematics)

**어디서 끊기나** — `movel(target_pos, ...)` (`robot_control.py:151`)
데카르트 좌표 6개(x, y, z, rx, ry, rz)를 넘기면, 관절각 6개를 푸는 건 컨트롤러 펌웨어다.
**내 파이썬 코드에 야코비안도 IK도 한 줄 없다.**

**이론이 시작되는 지점**
- 정기구학: 관절각 → 말단 자세. DH 파라미터, 변환행렬 곱 (축 1의 §1이 바로 이 도구다)
- 역기구학: 그 반대. 6축 산업 로봇은 **해석해(closed-form)가 존재**하고, 보통 **최대 8개의 해**가 나온다
  (어깨 좌/우 × 팔꿈치 위/아래 × 손목 뒤집힘)

**NotebookLM에 물을 것**
> 내 코드는 `movel`에 데카르트 좌표 6개를 넘기고 끝난다. 6축 로봇에서 그 뒤 관절각을 푸는
> 과정을 교재의 역기구학 챕터로 설명해줘. 해가 여러 개일 때 컨트롤러가 무엇을 기준으로
> 하나를 고르는지, 그 선택이 바뀌면 로봇 팔이 어떻게 달라 보이는지도.

**교재 위치** — Lynch & Park 『Modern Robotics』 6장 / Craig 4장

## 2. 야코비안과 특이점 (Singularity)

**어디서 끊기나** — **내가 쓴 노드에서는 한 번도 부르지 않는다.**
함수 자체는 두산 API 라이브러리에 있다:
`src/cobot_rg2/doosan-robot2/dsr_common2/imp/DSR_ROBOT2.py:3998`
```python
def set_singularity_handling(mode = DR_AVOID):   # ← 기본 인자가 DR_AVOID
```
이건 ROS 2 서비스 `motion/set_singularity_handling`을 부르는 래퍼다 (같은 파일 `:99`).
`src/robot_control`, `src/pick_and_place_*` 어디에도 호출이 없다.
즉 지금 내 코드는 특이점 근처에서 **무슨 일이 일어나는지 모른 채** `movel`을 부른다.

> 확인 필요: 호출을 안 하면 컨트롤러가 어떤 모드로 도는가?
> API의 기본 **인자**가 `DR_AVOID`인 것과, 컨트롤러의 기본 **동작**이 회피인 것은 다른 얘기다.
> 실기에서 확인하면 `docs/context/constraints.md`에 적을 것.

**이론이 시작되는 지점**
- 야코비안 $J(q)$: 관절 속도 → 말단 속도의 선형 사상. $\dot x = J(q)\,\dot q$
- **특이점 = $J$가 rank를 잃는 자세** ($\det J = 0$).
  역방향 $\dot q = J^{-1}\dot x$에서 $J^{-1}$이 발산 → **관절 속도가 무한대로 튄다**
- 이게 축 1의 "$\det R = 1$" 이야기와 같은 뿌리다: **행렬식이 0이 되면 정보가 무너진다**

**NotebookLM에 물을 것**
> 야코비안의 rank 손실이 왜 관절 속도 발산으로 이어지는지 특이값 분해(SVD)로 설명해줘.
> 그리고 특이점 회피 기법(damped least squares / 유사역행렬)이 수식적으로 뭘 바꾸는지.

> 참고: 유사역행렬 $J^+ = (J^\top J)^{-1}J^\top$는 축 1 §4에서 이미 봤다
> (`b_x = inv(C.T @ C) @ C.T @ d`). **같은 도구가 여기서 다시 나온다.**

**교재 위치** — Modern Robotics 5장 / Craig 5장

## 3. 자세(orientation) 추정 — 6D pose

**어디서 끊기나** — 여기는 "없다"가 아니라 **"반만 있다"**. 제일 중요한 구멍이다.

```python
target_pos = list(td_coord[:3]) + robot_posx[3:]   # robot_control.py:141
```

앞 3개(위치)만 비전에서 오고, **뒤 3개(자세)는 로봇의 현재 자세를 그대로 재사용한다.**

**결과**: 물체가 어느 방향으로 놓여 있든 **그리퍼는 늘 같은 각도로 내려간다.**
길쭉한 물체가 비스듬히 놓이면 못 집는다. 지금 코드는 위에서 수직으로 집는 것만 된다.

**이론이 시작되는 지점**
- YOLO 바운딩 박스는 **축 정렬(axis-aligned) 사각형**이라 방향 정보가 없다
- 방향까지 얻으려면: OBB(oriented bbox), 포인트클라우드 주성분분석(PCA),
  또는 6D pose estimation 모델
- **PCA는 순수 선형대수다** — 공분산행렬의 **고유벡터**가 물체의 주축이 된다. 고유값 분해가 여기서 쓰인다

**NotebookLM에 물을 것**
> 포인트클라우드에서 공분산행렬의 고유벡터로 물체 주축을 찾는 원리를 설명해줘.
> 고유값의 크기가 각각 무슨 의미인지, 그리고 축이 뒤집히는(sign ambiguity) 문제는 어떻게 다루는지.

**면접 가치 ★★★** — "지금 코드의 한계가 뭐죠?"에 대한 **완벽한 답**이다.
한계를 정확히 알고 해결 방향까지 말할 수 있으면 이긴다.

## 4. 궤적 생성 (Trajectory Generation)

**어디서 끊기나** — `vel=VELOCITY, acc=ACC` 두 숫자만 넘기고 끝이다 (`robot_control.py:151`).
A점에서 B점까지 **시간에 따라 어떤 속도 프로파일로 가는지**는 컨트롤러가 정한다.

**이론이 시작되는 지점**
- `movej` = 관절 공간 보간 (경로가 직선이 아니다), `movel` = 데카르트 직선 보간
  → **같은 두 점을 이어도 팔이 지나는 궤적이 다르다.** 코드에 둘 다 쓰고 있다 (`:146` vs `:151`)
- 사다리꼴 속도 프로파일 / S-curve(저크 제한) / 다항식 보간
- 회전 보간은 **SLERP**(쿼터니언 구면 선형 보간) — 오일러각으로 보간하면 안 되는 이유가 여기 있다

**NotebookLM에 물을 것**
> `movej`(관절 보간)와 `movel`(직선 보간)이 같은 시작/끝점에서 왜 다른 경로를 그리는지,
> 각각 어떤 상황에서 위험한지 설명해줘.

**면접 가치 ★★** — "movej랑 movel 차이가 뭐죠"는 단골 질문이고 **코드에 둘 다 있다.**

## 5. 힘 제어 · 임피던스 제어

**어디서 끊기나** — 전무하다. 그리퍼는 열고 닫기만 한다.
`task_compliance_ctrl` / `set_desired_force` 계열 호출이 **한 곳도 없다.**

```python
gripper.close_gripper()          # robot_control.py:153
while gripper.get_status()[0]:   # :155 — 닫히는 중인지 폴링만
```

**이론이 시작되는 지점**
- 위치 제어와 힘 제어는 같은 방향에서 동시에 못 한다 (한쪽을 정하면 다른 쪽은 환경이 정한다)
- 임피던스/어드미턴스 제어: 위치 오차와 힘의 **관계**를 설계한다 ($F = K\Delta x + D\Delta\dot x$)
- 물리량이 개입하므로 **툴 무게 보정**이 전제다 — 그리퍼 자중을 안 빼면 힘 측정이 통째로 틀린다

**NotebookLM에 물을 것**
> 위치 제어와 힘 제어를 같은 축에서 동시에 할 수 없는 이유를 물리적으로 설명해줘.
> 임피던스 제어와 어드미턴스 제어의 차이도.

**교재 위치** — Modern Robotics 11장 / RG2·두산 force control 매뉴얼
